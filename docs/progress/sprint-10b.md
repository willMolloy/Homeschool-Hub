## Decisions

- **S10-11 the four new hues are rose, leaf, aqua and plum,** not the README's example "apricot": apricot sits between honey and coral and was the closest pair on the wheel; leaf fills the empty green between butter/sage and mint. Each new fill meets the same checks as the first eight (ink 9:1 light, 6.5:1 dark; the amount at 5.2:1; strong tone 3:1 on its fill; AA labels on every child step).
- **S10-11 a colour that is not a swatch** (an older or hand-made one, like the demo's old Art green `#5c8a2f`) is still drawn as the nearest of the **first eight** only, so no family's existing colour changes hue when the palette grows. Stored colours are untouched; existing demo databases keep the old Art until reseeded or changed in S10-12.
- **S10-12 the swatch row wraps.** Twelve 44 px targets need 528 px, more than a 360 px phone has, so the "small row" is two rows of six on a phone and one row from about 560 px. Targets stay 44 px (they touch; the chips are 26 px).
- **S10-12 swatch names are the hue the parent sees** (Mint, not the stored swatch's old name Green), so "used by" names match what's on screen.
- **S10-12 the dot is dropped only where a badge replaces it** (subjects). Children have no badge, so their dot stays; the ticket's step 4 limits the children change to the 12 swatches.
- **S10-13 the switch is compact in both views.** It no longer stretches the full width, in Year too, so it does not change size when you switch views. Its row may still wrap below 320 px (a group that cannot fit drops to its own line rather than shrinking the 44 px arrows).
- **S10-13 the word sits over the range on a phone** rather than beside it ("This week · Nov 2 – Nov 8" needs ~170 px of text, which does not fit beside a 44 px arrow pair and the switch at 360). From 600 px it reads on one line as the ticket shows.
- **S10-09 the rail is one `nav`, restyled by width,** not a second component, so "never both" and "the same items in the same order" hold by construction. No smoke scenario reached Set up through Home's row (they open `/setup` directly), so none changed.
- **S10-09 the labels flag** is a build-time env var plus a dev-only query/device override; a production build ignores the query, so parents never see it.
- **S10-16 forms sit at the start of the column,** not centred inside it: a 480 px form under a 640 px heading lines up with the heading and the back link instead of floating.
- **S10-16 Week is capped like any page** (640 px); only Year, a timeline that reads across, is uncapped. The README lists Year as the exception and nothing else.
- **S10-16 "short related pairs" means start / end dates only.** Unit / Total and Weeks on / off were pairs in 10a; they are stacked now so every form reads top to bottom. A test checks every `.field-row` holds two date fields.
- **S10-16 the Add sheet preselects the first active subject** (the page form still preselects only when there is one) so the sheet opens ready to fill; the subject is one tap to change.
- **S10-16 R3 keeps the chips whenever they fit** (measured), and falls back to the select only if a name would still overflow, rather than truncating names.
- **S10-17 between 840 and ~952 px the wide pane is under 480 px.** Beside the 80 px rail, 840 px leaves 712 px, less than 480 + 24 + 320. DeeDee's 840 breakpoint wins: the narrow pane keeps its 320 px minimum and the wide pane takes the rest (368 px at 840), reaching 480 px from about 952 px. **Needs a decision if that is not wanted:** move the two-pane breakpoint to 952 px, or let the narrow pane shrink below 320.
- **S10-17 the narrow pane has no Set up row** (the ticket lists one): S10-09 removed it; Set up is in the rail.
- **S10-17 the panes are two layouts, not one reordered by CSS,** so the briefing / checklist / Schedule / Records reading order matches the screen at every width. Crossing 840 px (a window resize) remounts the cards; Home's own lists stay loaded, and the briefing refetches its plan once.

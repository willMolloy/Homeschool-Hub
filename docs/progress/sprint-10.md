## Decisions

- **S10-01 one more layer than the ticket names.** The Year edit sheet is not modal, so it gets its own `--z-edit` (20): above the tab bar (10), below the undo bar (`--z-toast`, 30) so Undo stays tappable over it, and below modal sheets (50) and dialogs (60). Dialogs sit one step above sheets so a confirm opened from a sheet is on top. Local layers inside a card (the lane popover, the date calendar, the More menu) use `--z-raised` / `--z-popover`. Every `z-index` in the app's CSS now uses a token, and a test fails on a bare number. The edit sheet keeps its place above the tab bar for now (S10-06 restyles it).
- **S10-02 the All subjects strip is removed.** The mockup has none; each child's load ribbon in their header row does its job. The ribbons share one scale (the busiest child's heaviest point in the view is the tallest, 12 px phone / 14 px desktop).
- **S10-02 Together header has no ribbon.** Shared work already shows in every child's ribbon, so the Together row is just the icon and "Together".
- **S10-02 a Together bar's thickness** is the larger of the children's plans on each day (they only differ where one child has a day off), titled "Title · F M" (four initials, then "+N").
- **S10-02 every bar uses the subject's base colour step.** The per-child light/dark steps are dropped, since the group header already says whose lane it is; this matches the mockup.
- **S10-02 bar heights are capped at the mockup's maximum** (28 px phone, 32 px desktop; sub-rows at 0.8) until S10-04 brings in effort-based heights. Rows sit at a fixed pitch, so an outside name now goes only where it fits above its bar inside its own row, or is dropped (S10-04b reworks names).
- **S10-02 the sticky header** has a 90% page-colour background, so the month lines show faintly through it. Only the header takes taps, so you can't tap a bar through a stuck header.
- **S10-09 rail labels:** an icon rail with small labels under the icons. Decided by DeeDee on 2026-11-03.
- **S10-15 overlapping zones.** Rows are 36/40 px apart, so neighbouring 44 px zones overlap by 4–8 px. Each zone keeps its full 44 × 44 box (so the tap-target check measures 44), and the click handler sends a tap in the overlap to the nearer badge centre. A stuck group header sits above the zones, so a tap on a header never selects a badge.
- **S10-03 the stuck group header is now opaque** (S10-02 used 90%). Scrolled in the browser, bars passing under a stuck header showed through it and looked like ghost bars. The mockup's header is opaque too.
- **S10-03 the axis is opaque, and so is its foot rule.** Nothing scrolls visibly under it, as in the mockup.
- **S10-04 reviewed 2026-11-04, percentile change approved by DeeDee:** the view maximum is the 95th percentile of loads in the current view, not the single heaviest; loads above it draw at the maximum.
- **S10-04 the percentile is taken over each assignment's daily load** (not a lane's sum), because overlapping work sits in separate rows, so a bar's height is its own load. It covers every lane in the view across the whole year (Together once), not just the visible month, so flipping ‹ › through This month doesn't rescale. Year uses the smoothed loads, so smoothing and scale agree.
- **S10-04 the smoothing window is picked by span,** so custom views get it too: more than 26 weeks smooths like Year (15 school days), anything shorter that is still drawn smooth like a term (5). Daily and weekly detail are not smoothed.
- **S10-04 extra rows use the same curve,** topping out at 80% of the maximum (`EXTRA_ROW_FACTOR`) with the same minimum.
- **S10-04 the smooth look keeps its 3 px dead band** (a held height changes only when the target moves 3 px or more) so a lumpy day-to-day plan has no tiny jogs; the curve eases between held heights, so there are no steps. The even-pixel rounding and the slope limit are dropped (rounding could push a bar past `BAR_H_MAX`; the moving average already keeps changes gradual). `calmSeries`/`limitSlope` removed from `smooth.ts`.
- **S10-04 heights are relative,** so a uniformly light plan looks the same as a uniformly heavy one; the difference shows between assignments and weeks in the same view. A child shown alone is rescaled to their own loads (expected; noted for the S10-10a tester).
- **S10-04 the ribbons use the same curve,** with their maximum at the 95th percentile of the children's daily totals.
- **S10-04 the dev override:** `bars=min,max,curve` (any part may be blank; bad parts are ignored). Raising the max grows the lane pitch (max + 8) and the sub-row step so bars never touch. Parsed only when `useDebugFlag()` is true (a dev build with `?debug=1`).
- **S10-04 outside names are rarer now:** with an 8 px minimum and a fixed pitch, few bars leave room above them, so most names sit inside or are dropped until S10-04b reworks names. The T-11d tests use a deliberately light lane.

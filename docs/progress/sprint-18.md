## Decisions

- **S18-01 one entry per save, even a no-op:** a save always records an entry. A save that changed nothing would otherwise leave an older entry on the API for the bar to offer, which would undo the wrong thing.
- **S18-01 label:** "Updated {title}" (the ticket's words). When the end date also moved it adds ", end moved to {date}". More than one assignment changed (not reachable from the screens) reads "Updated 2 assignments".
- **S18-01 undo order:** the check-ins go back first, then the assignment's end date, so restoring an earlier end never meets a newer check-in.

- **S18-02 what "Move" means now:** it moves the assignment's end date (as the late line's button does), where it used to store a `pushEndDate` check-in and let the engine find the end. The check-in is `keepEndDate` against the new end, so the plan reaches exactly the date the parent saw. Every child on the assignment gets the new end (an assignment has one end date).
- **S18-02 the suggestion is the briefing's date as the plan stands now,** not a simulation of the plan after the save: the engine's forecast needs two check-in weeks and the saved position, which only the server can replay. For the case in the run (already late) the two agree; where the forecast would only appear after this save, the sheet shows its shortfall estimate and the late line may then say a slightly different date. Not checked: a preview of the plan after the save.
- **S18-02 a stored `pushEndDate` is no longer prefilled:** the sheet has no way to say it any more, so it opens on Keep.
- **S18-02 the picked date's lower limit** is the end of the week being updated (the API's own rule is the latest check-in week, which is never later), checked in the sheet; the DateField has no min of its own.
- **S18-03 wording:** "chapters 16–17 (starts 17)", the ticket's first suggestion, because it reads left to right like the plain range and keeps "start" for the single-unit case; it says "starts N" only (never "continues"), since a unit the week reaches after the first is always begun in that week.
- **S18-03 the bar names what the days name, not what the week's end position says:** a day that finishes chapter 3 and begins 4 reads as the finish of 3 on Days (S16-11), so the bar names 3 and not 4 for that case. The bar and Days are the same by construction (`daySpans`), including that rule.
- **S18-03 a finished week uses the plan only when it still agrees** with the check-in row (the row is "as planned then", the plan is as it stands now); otherwise the old stateless words.
- **S18-03 capital letters** in "Chapter 17 · start" are left as they were here; S18-04 (E10) makes the range words lower case everywhere.
- **S18-04 E8 unit:** ticket says "no subject and no unit chosen (or the last used)"; both start empty on the Add sheet only. Add several, the page form and edits keep Lessons as the starting unit (nothing there was filing work under a surprise default).
- **S18-04 E9 minutes threshold:** the ticket's "about 165 min a day, that's a lot" is not a warning the single form had (it only warned on units a day, so 110 lessons in six weeks never tripped it). One function now serves all three: the unit note first, then more than 120 min a day for one assignment. 120 is my number; it is `MINUTES_NOTE_THRESHOLD`.
- **S18-04 E9 duplicates** are flags, not blocks (a parent may mean it); a "repeat" is same subject and title (case and spaces ignored) for at least one shared child.
- **S18-04 E7 identical** means every field the form sends matches, so Math today and Reading today as two entries are not warned about.
- **S18-04 E11:** the app has no per-child school days; days belong to each assignment, so a shared assignment runs on one set of days for every child. Building per-child days is a product change, not a small fix. The seed was the inconsistency (Wren Tuesday to Friday but sharing Monday read-alouds), so Wren now has her own copies of Gospel of Luke, The Hobbit, Our Island Story and the recitation on Tuesday to Friday (34 assignments). A test pins that Days and the sheet show nothing for a Tuesday-to-Friday child on Monday. If Will wants one shared assignment to follow each child's days, that is a new ticket.
- **S18-04 E12 Records choice:** its own key rather than a reset, so a parent's pick on Records is kept for next time.
- **S18-04 E13:** the Remove/Rename buttons and the twin prompt use the standard 44 px buttons.

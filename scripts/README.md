# scripts

## `check.sh`: the full gate
Run before every commit (`npm run check` does the same):

```bash
scripts/check.sh
```

Runs lint, typecheck, build, `db:reset`, test, test:tz and `db:validate`, stopping at the first failure with the tail of the log (full log: `$CHECK_LOG`, default `/tmp/hh-check.log`). It needs Postgres 16 and `DATABASE_URL` pointing at a `*_test` database (default `postgres://hh:hh@localhost:5432/hh_test`). That database is reset, and its role must be able to create the scratch database `hh_validate_test` that `db:validate` makes and drops.

CI (`.github/workflows/ci.yml`) runs the same steps.

## `smoke/`: browser smoke runs
Puppeteer scenarios that click through the running app and save screenshots to `docs/progress/screens`. This folder is **not** an npm workspace, so the app's install never pulls a browser driver.

```bash
cd scripts/smoke && npm install          # once
npm run demo                             # (repo root, another terminal) API + web dev servers on hh_dev
node flow.mjs login                      # runs scenarios/login.mjs
node shot.mjs http://localhost:5173/login /tmp/login.png 360
node manifest-check.mjs                  # PWA check against `npm run preview -w @hh/web` (port 4173)
```

Tap targets (S5-09): `node flow.mjs tap-targets` signs in, visits Home, Records, Schedule (Week, and Year with a bar selected), Set up, Children, Subjects, Assignments, Days off, Events and Family settings at 360 px (set `TAP_WIDTH`, e.g. `TAP_WIDTH=320 node flow.mjs tap-targets`, for another width from 280 to 1600), and also opens each screen's Add forms and template panels (Assignments' two Copy panels included), the timeline's Zoom views sheet, an edited row and its Archive/Delete confirm. It lists every visible button, link, input, select, textarea and summary under 44 by 44 px (a checkbox or radio is measured as its label; inline links in a sentence are exempt) and ends with "No undersized controls on the listed screens." or the total. It saves nothing. The demo family cannot add events; set `TAP_EMAIL` and `TAP_PASSWORD` to a non-demo login to measure the event form and its "What changes" list too.

**Scenarios on the Soft Paper screens (S8b-06).** Every scenario in `smoke/scenarios/` runs against the dev servers (`npm run demo`, 127.0.0.1). Routes follow Sprint 8 (`/setup/...`, `/schedule?view=week|year`, `/records`; the plan table needs `&debug=1`) and Sign out is the `signOut()` helper (the family button on Home). Dates are typed into the DateField as US text ("Nov 2, 2026") with `fillDates()` in `common.mjs`, which also checks the field shows that date (S9b-04). `records.mjs` covers Home (Schedule and Records), Records (Log setup, the log form, Export), Update status from a Week bar and the child switch (read-only; it replaced `track.mjs` when the Track work page went in S9-02). Scenarios that write need a family that is not the demo one, and two scenarios need an empty family: seed both once per `npm run demo` with
```bash
DATABASE_URL=postgres://hh:hh@localhost:5432/hh_dev npx tsx scripts/smoke/seed-second-family.ts
SMOKE_EMAIL=smoke@example.com node flow.mjs s2a-16-events      # also s2a-hardening, axe-2a, axe-log, s2a-13-settings, s2a-17
```
`kids-list` and `subjects-list` log in as `empty@example.com` (same demo password). The seed also makes `fresh@example.com`, a family that has not been through the first-run flow (Sprint 11): `node flow.mjs new-family` signs in as it, walks the setup flow with the breaks put off, checks Home shows only that reminder, then checks Schedule's Year shows one hint at a time. It writes to that family, so run the seed again before each run. `node flow.mjs completion` (Sprint 12) signs in as `smoke@example.com`, adds two assignments that ended yesterday, answers Yes, finished / Not yet / We stopped from Home, and checks the needs-you dot (its name, and that it clears), that Year draws the finished and stopped bars, that Not yet moved the end a week on, no sideways scroll and axe; it writes to the family, so reseed before each run. `node flow.mjs sheets` (Sprint 13, S13-06) signs in as the demo family (it writes nothing), opens Print sheets on Schedule · Week for a week and for a day (All children), and checks the print page: one sheet per child in order, no app bar or rail, white, a notes area, no minutes or effort words, Back to Schedule, no sideways scroll, axe, and (`page.pdf`) one page per child in Letter and A4; `window.print` is replaced so no dialog opens. `node flow.mjs term-review` signs in as `smoke@example.com`, sets up a log and logs two days per child through the API, opens Records, Term in review, checks the card's parts, that the printed card is light on a dark device, that Save image gives one 1080 x 1350 PNG per child (downloaded into a temporary folder) with no request but GETs, Print, and axe; it writes to the family, so reseed before each run. `node flow.mjs accounts` (Sprint 14, S14-06) makes its own family, so it needs no seed and leaves one new family with two parents in `hh_dev` (`npm run demo` resets it): it runs the `create-family-invite` command (needs `DATABASE_URL`, default the local `hh_dev`), opens the link on the join page (320 px, axe, 44 px), joins as the first parent and walks the setup flow to Home, checks that a used link and a made-up link show the same plain message, invites a second parent from Family settings and joins in a separate browser profile (same family, Home, no setup flow, both listed, the link can't be used twice), uses Add several and Undo, and checks that signing one parent out leaves the other signed in. `node flow.mjs view-only` (Sprint 15, S15-04) signs in as `smoke@example.com`, makes a view-only link with a label, joins it in a fresh browser profile as a viewer, browses Schedule (Week and Year, a bar's read-only detail), Records, Term in review and a print sheet at 320, 360 and 1280 px in light and dark (no sideways scroll, no control under 44 px, no edit control, axe), tries writes and closed reads from the viewer's page (all 403), checks a used and a made-up link read the same, then removes the viewer as the parent and checks the viewer's reload is refused. Run the seed first; it leaves the viewer removed and no link open. `node flow.mjs days` (Sprint 16, S16-03) signs in as the demo family (it writes nothing), checks Bars is the default, toggles Schedule · Week to Days (remembered after a reload) and, at 360 and 1280 px in light and dark, that all five days are on the page (side by side at 1280), no sideways scroll, no control under 44 px, axe, child and Together headings under All children, and that every Days line (child, day, title, range) equals the printed `/print/week` sheet's rows; a line opens the adjustment and nothing is written. Retired in S8b-06: `peek`, `tester-probe` (one-off probes of the old Plan page), `s2b-screens` (the weekly check-in card is gone; `records.mjs` now covers its successor, Update status), `tester-odd` and `tester2-odd` (they need hand-seeded odd-data families that are not in the repo; the API side is covered by `apps/api/test/tester2.schedule.test.ts`).

Environment: `SCREENS_DIR` (default `docs/progress/screens`), `CHROME_PATH` (default `/usr/bin/google-chrome`), `BASE_URL` (default `http://localhost:5173`), `PREVIEW_URL` (default `http://localhost:4173`).
Scenarios that add data leave rows in `hh_dev`; `npm run demo` resets it.
